# 📄 Project Synopsis — AI Powered Escape Room

## One-line summary
A browser-based 3D horror escape-room game in which an artificial intelligence
generates a fresh puzzle for every room, adapts its difficulty to each player,
and role-plays the ghosts you talk to — backed by a full Flask/SQL web platform
with accounts, cloud saves, a leaderboard, and an admin dashboard.

---

## 1. The idea
The player wakes with no memory inside a haunted library and must escape **ten
themed rooms** — Library, Temple, Prison, Laboratory, Hospital, Mansion, Castle,
Bunker, Cyber Facility, and a final Convergence. Each room is sealed by a lock
(keypad, riddle, or symbol-sequence) whose content is **generated by AI at run
time**, so no two playthroughs are the same. Between puzzles the player manages a
**flashlight**, a **sanity** meter, and a stalking **Presence**, and pieces
together a story that resolves in one of **three endings**.

The academic hook is that the "AI" is not set dressing: it drives puzzle
generation, tiered hints, free-text NPC dialogue, and narrative beats, with a
**server-side adaptive-difficulty engine** that rates each player's skill and
scales future puzzles to keep them in flow.

---

## 2. Technology
| Layer | Stack |
|---|---|
| **Rendering / game** | Three.js (WebGL2), Rapier physics, GSAP, custom HDR/PBR post-processing pipeline |
| **Frontend build** | Vite, vanilla ES modules, an event-bus architecture (no framework) |
| **Backend API** | Python, Flask, SQLAlchemy, JWT auth, bcrypt |
| **Database** | MySQL in production, automatic SQLite fallback for zero-config dev |
| **AI** | OpenAI (JSON mode) with a complete procedural fallback so the game works fully offline |
| **Audio** | 100% procedural WebAudio synthesis (no audio files) |

Every visual and sound asset is generated in code — there is no copyrighted
media in the project.

---

## 3. Architecture at a glance
- **Client** — a `Game` orchestrator wires independent systems (FPS controller,
  interaction, flashlight, sanity, haunt, rooms, puzzles, inventory, audio,
  saves, timers) that communicate through a global **event bus**. UI is a stack
  of DOM "screens" managed by a `ScreenManager`.
- **Server** — Flask blueprints split into `auth`, `game`, `ai`, and `admin`.
  Models cover users, saves, achievements, leaderboard, analytics, AI logs,
  room metadata, an authored puzzle bank, and settings.
- **AI service** — a single provider chain (OpenAI → procedural fallback) that
  logs every call for observability, used by puzzle/hint/dialogue/story
  endpoints and tuned per-player by the difficulty service.

---

## 4. Key features
**Gameplay**
- Real first-person controller (walk/run/crouch/jump, stamina, head-bob, focus
  zoom), aim-assisted interaction, and always-visible objective markers.
- Flashlight battery survival, a sanity system that distorts sight and sound as
  it falls, and the Presence that hunts in the dark and is banished by light.
- Three difficulty modes with server-enforced multipliers; a **per-room
  countdown timer** on Normal/Nightmare whose limit scales with each level and
  whose overtime drains sanity (and, on Nightmare, summons the Presence).
- Per-level **briefings**, an in-game **Field Manual**, journal, inventory with
  item combining, photo mode, gamepad support, compass, and speedrun splits.

**Platform**
- Accounts with JWT auth and password reset; local-first saves with cloud sync;
  achievements, a global leaderboard, and lifetime statistics.

**AI**
- Freshly generated puzzles, three-tier hints, free-text spectral dialogue, and
  story beats — all with graceful offline fallbacks and adaptive difficulty.

**Admin dashboard** (`/admin/`)
- Live statistics with an activity chart and an **active-players monitor**.
- **Add / edit / delete rooms** and tune their base difficulty.
- A **puzzle bank**: author keypad/riddle/sequence puzzles that the game serves
  in-game in preference to the procedural generator.
- Player management, puzzle analytics, AI-call logs, a raw event stream, and
  **leaderboard moderation** (delete a run or reset all data).

---

## 5. What makes it notable
- **AI is core, not cosmetic** — generation, hints, dialogue, and adaptive
  difficulty are all model-driven, yet the game is 100% playable offline.
- **Zero-config to run** — one command starts both servers; SQLite fallback and
  procedural asset generation mean no external setup is required.
- **Full-stack breadth** — a real-time 3D client, a secured REST API, a
  relational data model, and an operator-facing admin panel in one project.
- **Self-contained** — no third-party art or audio; everything is synthesized.
