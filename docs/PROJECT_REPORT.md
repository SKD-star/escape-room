# Project Report — AI Powered Escape Room

**Final Year Project**
**Stack:** Three.js · Rapier · GSAP · Flask · SQLAlchemy · MySQL · OpenAI API

---

## 1. Abstract

AI Powered Escape Room is a browser-based 3D horror escape game in which the
puzzles themselves are generated by a large language model and tuned to each
player's measured skill. The player traverses ten themed environments —
from a haunted library to a rogue AI facility — solving keypad, riddle and
symbol-sequence puzzles, conversing in free text with spectral NPCs, and
collecting items whose combinations determine which of three endings they
reach. The system is offline-first: every AI feature has a deterministic
procedural fallback, and every cloud feature (auth, saves, leaderboard) has a
local equivalent, so the game is fully playable with zero configuration.

## 2. Objectives

1. Demonstrate integration of generative AI into core gameplay (not cosmetic):
   puzzle generation, tiered hinting, NPC dialogue, narrative beats.
2. Implement measurable **adaptive difficulty** from behavioral analytics.
3. Achieve commercial-grade presentation in the browser: PBR rendering,
   postprocessing, physics, positional/procedural audio, cinematic UI.
4. Deliver a complete product: auth, persistence, leaderboard, achievements,
   admin analytics, documentation and deployment.

## 3. System Architecture

Three tiers (full diagram in `ARCHITECTURE.md`):

- **Client** — Vite-bundled ES2022 modules. An `Engine` class owns the WebGL2
  renderer and a postprocessing composer (bloom, SSAO, DOF, chromatic
  aberration, film grain, vignette, color grade over an HDR half-float
  pipeline with ACES tone mapping). A global `EventBus` decouples ~15
  subsystems; no gameplay system imports another directly.
- **Server** — Flask app factory with three API blueprints (auth, game, ai)
  plus an admin dashboard blueprint. JWT auth (24 h), bcrypt passwords,
  per-IP rate limiting, strict input validation.
- **Data** — SQLAlchemy over MySQL (SQLite fallback for development).
  11 tables covering users, saves, achievements, leaderboard, analytics,
  puzzle history, AI logs, rooms and settings.

## 4. Key Technical Decisions

| Decision | Rationale |
|---|---|
| **Procedural assets** (canvas-painted PBR textures + primitive-composed props) | Zero copyright risk, ~1 MB total download, reproducible via seeded RNG; normal maps derived from albedo via Sobel filter |
| **Rapier (WASM) over cannon-es** | Built-in kinematic character controller (autostep, snap-to-ground, slope limits), better performance |
| **Server-side AI with client fallback chain** | API key stays secret; OpenAI → server procedural → client local gives 3 layers of resilience |
| **EMA skill rating** | `rating ← 0.75·rating + 0.25·performance` where performance combines solve time and hint penalties; next difficulty = 0.4·room base + 0.6·(0.8·rating+0.15), clamped to keep players in flow |
| **Procedural WebAudio** | All sounds synthesized (filtered noise bursts, detuned oscillator drones, LFO-modulated wind) — no audio files, per-theme ambience recipes |
| **Offline-first persistence** | localStorage always written; cloud mirrored when authenticated; newest-wins merge on load |

## 5. AI Integration Details

- **Puzzle generation** — JSON-mode chat completions with a strict schema
  (type, narrative, solution fields). Responses validated; malformed output
  falls back to the procedural generator. Every call logged (`ai_logs`) with
  provider, latency and success for admin review.
- **Hints** — 3 escalating tiers (cryptic → directional → near-answer),
  generated against the actual puzzle JSON.
- **NPC dialogue** — each room has a themed spirit with a character system
  prompt; the last 6 exchanges are replayed for continuity. Mood tags drive
  potential presentation changes.
- **Adaptive difficulty** — analytics events and puzzle results continuously
  update the player's skill rating, which parameterizes both the AI prompt
  ("difficulty 0.72, 0 easy / 1 brutal") and the fallback generator (code
  length, riddle pool, sequence length).

## 6. Gameplay Systems

- **FPS controller:** pointer-lock look, walk/run/crouch/jump, stamina with
  regen, head-bob synced footstep events, breathing sway, camera shake bus.
- **Interaction:** center-screen raycast; interactables expose label +
  callback; objects support pick-up → inspect (mouse rotation) → throw
  (impulse into Rapier dynamic body).
- **Puzzles:** keypad, riddle (free-text with fuzzy match), symbol sequence;
  diegetic clue drip via toasts/notes after 45 s.
- **Inventory:** collection, inspection lore text, pairwise combination
  recipes; combined items gate the true ending.
- **Endings:** standard / true (crafted memento) / dark (hint overuse) —
  submitted to the leaderboard with score formula rooms×1000 + puzzles×250 −
  time/6 − hints×100.
- **Achievements:** 12 (2 secret), unlocked locally and synced.

## 7. The Ten Rooms

Each room subclass builds unique geometry, materials, lighting and scripted
behaviors (~150-250 lines each): Haunted Library (secret bookshelf lever,
ghost librarian), Ancient Temple (brazier GI, pulsing runes), Forgotten
Prison (swinging spotlight, barred cells), Abandoned Laboratory (glass
specimen tanks, flickering fluorescent RectAreaLight), Abandoned Hospital
(morgue drawer puzzle wall, heart monitor blips), Haunted Mansion
(chandelier, pendulum clock, mirror scare), Medieval Castle (throne dais,
armor stands, six torches), Secret Bunker (radio wall with animated dials,
codebook under bunk), Cyber AI Facility (server-rack blinkenlights, pulsing
AI core, glitching data-ghost) and the Final Convergence (orbiting debris,
ten floating doors, an eye entity that tracks the camera, storm lightning).

## 8. Performance

- Quality presets (Low → Ultra) scale pixel ratio, shadow resolution,
  SSAO/DOF toggles and particle counts.
- A runtime **PerfGuard** samples 5 s FPS windows and steps quality down
  automatically after two consecutive sub-45 fps windows.
- Bundle: split chunks (three.js 247 KB gz 103 KB; effects 720 KB; Rapier WASM
  2.2 MB gz 842 KB — lazy-loadable), total first paint < 1 MB gzipped
  excluding physics.
- Frame loop clamps dt, fixed-step physics accumulator, full GPU resource
  disposal on room transitions (verified via renderer.info).

## 9. Testing

- **Backend:** endpoint smoke tests (register/login/AI/saves/leaderboard/admin
  stats) via curl during development; all returning expected payloads.
- **Frontend:** headless Chrome (CDP) automated boot test — asserts zero
  console errors to main menu; per-room load test cycling all 10 rooms
  (caught and fixed a missing canvas helper and a physics lifecycle crash);
  screenshot verification of menu and three rooms.
- **Security:** bcrypt(12), JWT expiry, rate limiting on auth/AI, save-size
  caps, HTML escaping in all UI injection points, account-enumeration-safe
  password reset.

## 10. Limitations & Future Work

- Physics colliders are box approximations; convex hulls would improve throws.
- Multiplayer (socket.io is already a dependency) — co-op puzzle solving.
- Whisper integration for voice-controlled NPC dialogue.
- GLB asset pipeline is implemented (Draco-capable loader + cache) but ships
  no external models; curated CC0 packs would raise visual fidelity further.
- ElevenLabs TTS for spoken ghost dialogue.

## 11. Conclusion

The project meets its objectives: a complete, documented, deployable 3D web
game in which AI is load-bearing — generating the puzzles, pacing the
difficulty and voicing the characters — while remaining fully functional
offline. The architecture (event-driven client, layered AI fallbacks,
offline-first persistence) is the main engineering contribution and is
directly reusable for other AI-driven game projects.
